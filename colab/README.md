# Colab Workspace

This folder isolates Colab assets from the root project.

## Structure

- `notebooks/`: Colab notebooks for preprocessing and evaluations
- `env/`: Minimal `uv` project used by Colab notebooks

Notebook additions:

- `notebooks/colab_ragtruth_baseline.ipynb`: Reproduce RAGTruth baseline flow in Colab (prepare dataset, local model inference, and case-level precision/recall/F1).
- `notebooks/colab_demo_rag_longt5.ipynb`: Run baseline RAG demo with fixed `google/long-t5-tglobal-base` using a local Colab repo/venv and Drive-hosted artifacts routed via `data` symlink, then export `rag_demo_results_*.json`.

## Dependency model

Notebooks install dependencies with:

1. `uv sync --project colab/env --extra <group>`
2. Fallback to root `requirements.txt` if `uv` fails

Extra groups used by notebooks:

- `preprocessing` → `colab_wikipedia_preprocessing.ipynb`
- `evaluation` → `colab_evaluation.ipynb`
- `mitigation` → `colab_mitigation_evaluation.ipynb`

### FAISS note

- Colab env manifests use `faiss-cpu` for compatibility across current Python/CUDA images.
- Local environments also use `faiss-cpu` by default.
- Runtime still has CPU fallback in code if FAISS GPU runtime is unavailable.

## Notes

- `colab_demo_rag_longt5.ipynb` uses a local repo at `/content/AIST-FYP` by default for faster dependency setup.
- For `colab_demo_rag_longt5.ipynb`, large artifacts are expected under a Drive data root and are mapped into the local repo through a `data` symlink.
- Other notebooks may still clone/use the main repo at `/content/AIST-FYP`.
- Script execution remains plain `python ...`; after `uv sync` the notebook prepends `colab/env/.venv/bin` to `PATH`.
- Keep root `requirements.txt` as compatibility fallback for unstable Colab images.

## Running Full Evaluations

Most evaluation notebooks in this directory feature a **Smoke Test** mode by default (e.g., `MAX_SAMPLES = 10`). This allows for rapid verification of the pipeline and environment setup without the cost and time of a full dataset run.

**To run the full pipeline:**
1. Open the notebook's **Parameters** or **Configuration** cell (usually near the top).
2. Locate variables such as `MAX_SAMPLES`, `RAGTRUTH_MAX_SAMPLES`, or `CITEEVAL_MAX_SAMPLES`.
3. Change the value from the default integer (e.g., `10`) to `None`.
4. Run the notebook from the top.

## Running Full Pipeline UI in Colab

The full Gradio confidence UI can be launched from a Colab runtime with:

- `python scripts/demo_full_pipeline.py --share --server-name 0.0.0.0 --server-port 7860 --force-non-interactive`

Notes:

- `--share` is required for a public URL that can be opened from Colab output.
- `--force-non-interactive` avoids terminal prompts and auto-selects the first available strategy when multiple indices exist.
- You can pin a strategy explicitly with `--strategy development|validation|production`.

## Large Artifact Download (Local)

For large Step 7 packages generated by `colab_wikipedia_preprocessing.ipynb`, use:

- `python scripts/download_colab_packages.py --source "gdrive:AIST-FYP-colab-preprocess/<run_folder>/download_packages" --dest "<local_target_dir>/download_packages" --tool rclone`

This local script can:

- Download via `rclone` or `gsutil`
- Verify SHA-256 checksums for split parts
- Reconstruct `.tar.gz` archives (and optionally extract)
